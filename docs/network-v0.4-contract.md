# RouterTop 0.4 implementation and acceptance contract

Base: 7af518d. User requests IPv6, WireGuard full tunnel, local console authentication, persistent Web controls, a compact Apple-style light interface, actual testing and commit/push to the existing public repository.

Owners: network-v04 worktree owns lib.rs/network.rs/ipv6.rs and network/IPv6 tests. console-v04 owns web.rs/console.rs, console tests, inittab and console wrapper, then the new network-v04-smoke.py. web-v04 owns web assets, design-v0.4.md and browser-v04-smoke.py. Root owns main.rs, build/runtime integration, version, docs, VM and TTY acceptance. Files are transferred by scope; no author overwrites another author. Independent reviewer checks final integrated candidate once.

IPv6 config: optional Config.ipv6, default null. Fields wan_address/wan_gateway (paired optional strings; static WAN IPv6, optional only with dual-stack full tunnel), lan_address (host /64), vlans [{interface,address /64}], dns_upstream [IPv6 addresses]. Typed strict validation; no overlaps, malformed/injected values, multicast or link-local LAN prefixes. DNSmasq supplies RA/SLAAC. WAN DHCPv6-PD is not included in this iteration. HTTPS management remains on trusted IPv4 LAN. FirewallRule gains family ipv4(default)/ipv6 and protocol icmpv6; reject mismatched CIDR/protocol families. Default deny with necessary IPv6 ND/error/PMTU traffic; generated input and forward policies remain scoped.

WireGuard gains address_v6:null, full_tunnel:false,nat66:false. Full mode requires internet=false, a single peer with IPv4 default and optional IPv6 default, and literal IPv4 endpoint. At most one full-tunnel interface. Separate policy table 51820 plus mark 0x5254, main nondefault routes and marked encrypted UDP retain underlay/local reachability. All configured WG sockets receive reserved mark when full active. WAN output permits only marked WG UDP source ports, DHCPv4 and necessary IPv6 ND, then drops; forwarding to direct WAN drops before established/custom. IPv4 NAT to VPN is enabled; NAT66 is explicit, otherwise remote return routing required. IPv4-only full mode blocks IPv6 forwarding rather than leaking. Dropping/removing the tunnel must not permit plaintext fallback. All state persists with existing atomic config/key bundle; network changes activate at reboot.

Console: mandatory auth on ttyS0 and tty1, using the same persistent admin Argon2 password as Web. No unprotected shell on failures/corrupt or absent data. First boot offers create or token; create asks New password and Confirm password, token displays existing bootstrap token only on the physical terminal. Registered console asks Password then starts root shell after successful authentication; exit returns to login. Ctrl-C/EOF/wrong password must not grant shell. Echo disabled before password prompt and restored safely. Shared root-owned console throttle across TTY, separate from Web runtime. Root state writes retain UID/GID so Web UID1000 still reads/writes. Web password changes affect subsequent console login immediately. No disable-auth toggle. GET status reports console_auth_required and console_password_shared.

UI: macOS System Settings-inspired light gray sidebar, white grouped panels, blue emphasis, system fonts and restrained borders. RouterTop branding, no Apple assets, CDN or framework. Readable contrast, visible keyboard focus, skip link, responsive controls, all existing actions retained. IPv6 and full tunnel controls explain static WAN, NAT66, reboot and leak protection clearly. Console credential sharing shown in account settings.

Acceptance: Windows/Alpine tests, old config migration, IPv6 packet forwarding/RA/typed firewall, real dualstack WG handshake and full-tunnel egress, no WAN fallback after tunnel deletion, no IPv6 bypass in IPv4 full mode, actual TTY initial enrollment/wrong password/success/logout/password change/EOF+interrupt/root ownership, Web CRUD+reboot persistence and visual/keyboard/mobile verification, BIOS/UEFI 256MiB attempts, artifact hashes/size, public commit+push and actual CI. Never publish credentials, private keys, session cookies or populated data disks. Kernel+compressed-root target remains <=64MiB; ARM reserved, untested hardware stated explicitly.
